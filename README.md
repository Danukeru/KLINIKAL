# klinikal-linux

Linux port of KLINIKAL (github.com/Danukeru/KLINIKAL, upstream LICENSE
retained; upstream docs and the Windows build live in the upstream
repo). Upstream KLINIKAL is a Go Winsock2 proxy DLL that routes
Windows socket calls through an embedded wireguard-go + gVisor
netstack. This port is not a shim: the Go module (linuxsock/)
implements the POSIX socket API natively — fd-numbered operations,
Linux errno errors, glibc fd_set/pollfd/addrinfo layouts, Linux
option/ioctl numbers — and the C part is a thin LD_PRELOAD loader.
Any Linux process (here: CPython) gets its AF_INET/AF_INET6 socket
calls routed through the WireGuard tunnel; AF_UNIX, pipes and files
pass through to libc via RTLD_NEXT.

## Layout

- linux_preload.c   the LD_PRELOAD loader. Its jobs: interpose the
  libc socket entry points and dispatch fake fds to the Go stack;
  own the fd namespace (fake fds below FD_SETSIZE reserved with
  hidden /dev/null fds, so CPython's fd_set bitmaps stay valid —
  the fd number IS the identity the Go side keys on); emulate epoll
  for tunnel fds via the eventfd bridge; split mixed real+tunnel
  select/poll across the two backends. No protocol or layout
  translation happens here.
- linuxsock/        the socket stack, POSIX-shaped:
  - socket.go     socket()/dup()/close() (fd registration + refcount
                  aliases)
  - connect.go    bind/listen/accept/connect (EINPROGRESS semantics);
                  parseSockAddr accepts AF_INET and AF_INET6
                  sockaddrs, mapping v4-mapped (::ffff:a.b.c.d) to
                  IPv4 — dual-stack clients like gRPC hand over
                  AF_INET6 even for IPv4 targets
  - io.go         send/recv/sendto/recvfrom (MSG_PEEK, EAGAIN,
                  per-socket mutex)
  - poll.go       select/poll over glibc fd_set bitmaps and struct
                  pollfd, event-driven via gVisor waiter queues
  - options.go    setsockopt/getsockopt/ioctl with Linux level,
                  optname and request numbers
  - dns.go        getaddrinfo/freeaddrinfo/getnameinfo producing
                  glibc-layout addrinfo chains and glibc EAI codes
  - errors.go     errno model + gVisor error -> errno mapping
  - registry.go   fd -> SocketState registry (the fd namespace)
  - notify.go     eventfd bridge for the loader's epoll
  - waiter.go     gVisor waiter plumbing
  - stack.go      wireguard-go device + netstack bring-up
  - init.go       InitStack/ShutdownStack
  - addr.go       address-family constants and sockaddr helpers
  - inet.go       C string interop helpers
  - log.go        KLINIKAL_VERBOSE tracing
  - services.go   static protocol/service tables for getaddrinfo
- exports.go        the cgo export surface: the POSIX socket API
  itself (go_socket(fd,...), go_connect(fd,...), go_select with
  bitmaps, go_poll with native pollfd, ...). ~22 functions.
- init_linux.go     klinikal_init(): stack bring-up called from the
  loader constructor
- main.go           empty main required by -buildmode=c-shared
- build.sh          go build -buildmode=c-shared -> libklinikal.so
  (regenerates libklinikal.h)
- setup_wg.sh       host wg0 tunnel + NAT for DNS-through-tunnel +
  tunnel-only HTTP test server on 10.9.9.1:8099
- run_test.sh + test_preload.py   the proof suite (23 cases)
- wg.conf           generated by setup_wg.sh (client 10.9.9.2)

## Build & run

    bash build.sh
    sudo bash setup_wg.sh          # wg0 + NAT + test server
    bash run_test.sh               # expects PROOF_OK

Usage in any process:

    LD_PRELOAD=$PWD/libklinikal.so KLINIKAL_WG_CONF=$PWD/wg.conf python3 ...

Debug tracing: KLINIKAL_VERBOSE=1 prints socket call traces, waiter
notifications, and eventfd-bridge registration.

## What is verified (test_preload.py, all pass)

Layer 1 (data path): urllib fetch of http://10.9.9.1:8099 (bound to
the tunnel-only address; the netstack has no other route), DNS for
example.com through the tunnel's 1.1.1.1, wg0 counters confirm the
traffic went through WireGuard.

Layer 2 (async): socket-timeout recv (FIONBIO -> EAGAIN -> CPython's
internal select), selectors.DefaultSelector (epoll),
selectors.PollSelector (poll), select.select, non-blocking recv.

Production: non-blocking connect (EINPROGRESS -> writable ->
SO_ERROR=0) and refused connect (SO_ERROR=111), fd-range check,
os.dup aliasing with refcounting (closing an alias keeps the
original alive), dup3() aliasing, sendmsg/recvmsg scatter-gather,
4-thread concurrent connect+epoll+fetch.

Stability regressions: 300 getaddrinfo loops (addrinfo ownership
predicate, no fixed C table), 8-thread epoll registration churn
(mutexed epoll table), fd-reservation race (kernel-allocated
reservations; see Architecture notes), SO_RCVTIMEO bounded blocking
recv (raises socket.timeout against a 1s-delay endpoint; no-timeout
recv still waits), MSG_DONTWAIT per-call non-blocking recv, close
during EINPROGRESS (abandoned dial discards its connection; stack
stays healthy), MSG_PEEK completeness (peek returns everything
buffered at that instant and the following recv sees identical
bytes), close_range via libc + os.closerange (fake range cleaned,
real range passthrough), mixed pipe+tunnel poll through the single
bridge wait (1.00s wall, ~4ms CPU).

Passthrough regressions: cross-process loopback IPC (parent accepts
on a fake fd that swaps to real at bind(127.0.0.1); child connects
through the kernel and gets its data), AF_UNIX socketpair-style
bind/connect/send/recv untouched by the loader.

Event-driven proof: a server that responds at exactly 1.0s wakes
epoll_wait at 1.001-1.002s, and a 2s idle epoll wait costs ~1.4ms CPU
(baseline 0.1ms).

## Architecture notes

- Routing rules (what goes through the stack, what does not):
  - socket(): only AF_INET/AF_INET6 SOCK_STREAM/SOCK_DGRAM become
    fake fds; every other domain (AF_UNIX, packet, raw variants)
    returns the real libc socket directly. AF_INET6 fake sockets are
    accepted because dual-stack clients (gRPC) create them and then
    connect to v4-mapped ::ffff:a.b.c.d addresses, which the stack
    maps to IPv4; a true IPv6 target fails routing (EHOSTUNREACH).
  - every socket entry point checks KL_IS_FAKE first; a real fd is
    always served by libc via RTLD_NEXT. This is what lets mixed
    processes (kernel fds + tunnel fds) coexist.
  - loopback stays on the kernel: bind()/connect() naming
    127.0.0.0/8 or ::1 on a fake fd swaps the fd in place to a
    real socket (kl_swap_to_real: build real socket of the same
    domain/type, dup2 over the placeholder so the fd number never
    changes, mirror SO_REUSEADDR/non-blocking, drop the stack
    registration). Each injected process embeds its OWN stack, so
    127.0.0.1 cannot be an IPC path between two of them.
- One fd namespace: the loader allocates fake fds by opening a hidden
  /dev/null placeholder — the number the kernel returns is
  atomically the app's lowest free fd and is registered in Go under
  that same number. (Targeted-slot dup3 reservation loses a race
  against the kernel's own get_unused/fd_install window, so it is
  used only where the app explicitly requests a number: dup2,
  F_DUPFD with a floor.) There is no handle space and no
  fd<->handle mapping.
- errno end to end: the Go side records Linux errno values; the
  loader's KL_FAIL() just sets errno from klinikal_last_error().
- getaddrinfo: the Go side writes glibc-layout addrinfo chains
  (socklen_t addrlen, canonname last, Linux AF values, negative
  glibc EAI codes); the loader passes the chain through and hands
  the head back to Go on freeaddrinfo.
- epoll via eventfd bridge: the Go side creates an eventfd per
  registered tunnel fd and hooks it into gVisor's waiter queue
  (SocketState.NotifyEvent -> eventfd write); the loader adds that
  eventfd to the real kernel epoll with a token-tagged data.u64.
  epoll_wait blocks in the kernel and wakes exactly on state
  changes. Entries registered before connect completes (no waiter
  queue yet) retry the bridge lazily and fall back to 10ms slice
  polling.
- poll()/select() share the same bridge: kl_mux_wait() builds one
  combined pollfd array (real fds + the bridge eventfd of every fake
  fd, created on demand via go_start_notify) and blocks in a single
  kernel poll(); on an eventfd wake it drains, computes true revents
  via a zero-timeout go_poll, and re-arms if still hot.
- Non-blocking connect: an async dial goroutine (DialDone channel +
  DialErr); writability gates on it and getsockopt(SO_ERROR)
  returns the dial result as errno.
- dup/dup2/F_DUPFD_CLOEXEC: the loader reserves the target fd and
  calls go_dup; the Go side keeps a shared refcount + shared mutex,
  and the underlying socket closes with the last alias.
- Thread safety: per-socket mutex in the Go side serializes
  send/recv/readiness-probe on the shared peek buffer; a pthread
  mutex guards the C fd/epoll tables.
- CPython specifics handled: os.dup is fcntl(F_DUPFD_CLOEXEC);
  recvmsg_into passes msg_name on TCP (falls back to recv +
  getpeername on EINVAL); the connect-wait uses ppoll, which is
  interposed; C-level fd_set bitmaps require fds < 1024.

## Port gotchas found the hard way

- glibc struct addrinfo has ai_addr at offset 24 (4-byte socklen_t,
  canonname last); the winsock layout upstream writes has it at 32
  (8-byte uintptr, canonname before addr). The layouts are now
  glibc-native in the Go side; entries with NULL ai_addr / zero
  addrlen must still be filtered.
- winsock fd_set is a COUNT+ARRAY of SOCKETs, not a bitmap; WSAPoll
  event constants and winsock timeval differ from Linux. All gone
  with the POSIX conversion — kept here as history.
- setup_wg.sh needs iptables (not installed by default on this box)
  and ip_forward+MASQUERADE for DNS-through-tunnel.

## Known limitations

- Mixed real+tunnel poll()/select()/epoll() all block in the kernel
  via the eventfd bridge; 10ms slice loops remain only for fds whose
  bridge cannot exist yet (connect in progress).
- close_range() is interposed on the libc symbol path (os.closerange
  routes correctly); a raw syscall(SYS_close_range, ...) bypasses
  LD_PRELOAD and would leak the Go-side registration for the closed
  fake fd.
- MSG_PEEK tops up from the stack after serving parked bytes, so a
  peek returns everything buffered at that instant; bytes arriving
  after the peek are of course not included.
- sendmsg/recvmsg flatten iovecs through one stack call (no native
  scatter/gather in the stack).
- FIONREAD reports only bytes parked by MSG_PEEK/readiness probes
  (a Go net.Conn cannot report buffered bytes without reading).
- fork() without exec: the child inherits a Go runtime that is not
  fork-safe; a forked child touching a tunnel socket hangs. Use
  spawn/forkserver multiprocessing (Python's default on Linux for
  many stacks; plain fork-based mp needs the tunnel closed before
  forking).
- fd table ceiling: fake fds must stay below FD_SETSIZE (1024) for
  C-level fd_set bitmaps, so a process can hold ~1000 concurrent
  tunnel sockets before socket() returns EMFILE. Kernel fds are
  unaffected.
- DNS is globally hijacked: getaddrinfo is interposed, so ALL name
  resolution in the process goes through the tunnel's resolver.
  Split-horizon or localhost-only names should be resolved by
  literal address or via /etc/hosts-independent paths.
- pselect's sigmask argument is not emulated (the wait goes through
  the poll bridge); EPOLLET gets level-triggered behavior (the
  eventfd bridge re-arms on any readiness).
- Cost per call: userspace stack + WireGuard crypto + cgo hop.
  Throughput-bound workloads pay it on every send/recv; control-
  plane traffic is fine (see integration notes).

## Integration findings (Ray deployment, ~/DEVEL/muloco-ray/klinikal-ray)

Proven: an LD_PRELOAD-injected Python driver completes the entire
Ray control-plane handshake — ray.init, GCS gRPC, raylet gRPC,
cluster listing — entirely through the userspace stack over the
WireGuard tunnel. Requirements: v4-mapped AF_INET6 support (above),
GRPC_POLL_STRATEGY=poll (the epoll1 gRPC engine misbehaves over
injected fds), and a tunnel pre-warm before ray.init (a cold WG
handshake ~15s eats gRPC's 5s connect deadline).

The hard boundary: every Ray core worker (driver AND workers) hosts
a gRPC server advertised at the NODE IP. An injected process's
listeners live inside its private userspace stack and are invisible
to kernel-net peers at that address — actor creation retries forever
("Actor creation task failed, will be retried"), the raylet reports
"Core worker <node-ip> has been unavailable". Transparent-bind would
fix the listen but poisons every outbound connection to that address
(the stack delivers it locally). Frameworks that assume one IP per
node cannot mix kernel-net and stack-net processes as peers:
client-through-tunnel works, server-behind-tunnel does not.

Also learned there: Ray runtime_env env_vars DO reach the worker
exec env (LD_PRELOAD included), so workers get injected even when
the driver is not; and killed drivers leave orphan actors retrying
forever and holding custom resources — restart the cluster between
runs.
